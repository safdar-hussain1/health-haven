Hospital Management System

Health Haven

A hospital runs on answers to small, unforgiving questions. Which beds are free? How long has this patient been in one? What do they owe? Health Haven answers them — admissions, wards, billing, payroll, ambulance dispatch and an audit trail — behind a layered Java domain model, one embedded database, and three interfaces onto the same rules. Everything on this page is exported by the running application.

What it does

Eight capabilities, all of them driven by the same service layer — whether you reach them from the desktop client, the console, or over HTTP.

🛏

Admissions

Admit a patient into a free bed, or refuse: an occupied room is rejected by the database itself, not by a hopeful flag.

🧾

Billing

Nights × rate, plus procedures, pharmacy and transport, less the deposit. An over-deposit is a refund, stated as one.

🏥

Ward map

Occupancy derived live from active admissions across four ward types, from the general ward to intensive care.

👥

Patients

A permanent medical record number per person. Discharge closes the stay; it never deletes the patient.

💰

Payroll

Each staff class computes its own pay from its own rules. Payroll sums a mixed list without asking what's in it.

🚑

Dispatch

Send an ambulance and recall it. One vehicle cannot be sent to two emergencies at once.

🔐

Access control

Bcrypt passwords and role permissions checked in the service layer, so a disabled button is a courtesy, not a control.

📜

Audit log

Append-only. Every mutation records who did it, to what, and when. Nothing in it is ever updated or deleted.

How it's built

Four layers, each depending only on the one beneath it. The domain layer does not import java.sql and has no idea a database exists — which is why it can be tested without one, and why the three interfaces are interchangeable.

ui/ · cli/ · web/Swing desktop · console · JSON API
↓
service/rules · permissions · transactions
↓
repository/interfaces · JDBC, always parameterised
↓
domain/Person · Admission · Money · BillableItem

Rules the database itself enforces

Application code is the first line of defence; the schema is the last.

  • One active admission per room — a partial unique index, so two patients in one bed is impossible, not merely unlikely
  • One active admission per patient
  • An admission is ACTIVE with no discharge time, or DISCHARGED with one — never both
  • One ambulance, one open dispatch
  • Money is INTEGER paise — never a float, never a string
  • Every stay bills at least one night
  • audit_log is append-only

Three ways in, one set of rules

Each surface is a thin adapter over the services. None of them contains a rule, so none of them can disagree with the others.

The Swing client — FlatLaf, real layout managers, with admit, discharge and dispatch as working actions.

Why it's built this way

Several decisions here cost more than the obvious alternative — parameterised SQL, an invoice that knows about length of stay, discharge as an archive, occupancy derived rather than stored. The naive/ package implements the obvious alternative, so the difference can be measured instead of argued about. Reproduce all of it with java -jar health-haven.jar audit.

The expensive one

Bill a stay as rate − deposit and it reads fine — until you notice rate is the price of one night, and the length of stay is nowhere in it. Replayed across the 40 invoices this hospital has actually issued:

A 91.3% shortfall, and all 40 bills come out negative — the screen would tell the desk clerk that the hospital owes the patient money.

The other three

  • Concatenated SQL lets anyone in. Build the login query by string concatenation and the password ' OR '1'='1 signs you in as anybody. Health Haven binds parameters and verifies a bcrypt hash.
  • Discharge as a delete loses the patient. delete from patient and the hospital forgets everyone it discharges. Health Haven archives the stay and keeps the person.
  • Occupancy as a flag double-books beds. A text column that every screen must remember to update drifts out of step. Health Haven derives it, and the database refuses the second admission.
