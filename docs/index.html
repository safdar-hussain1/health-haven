Health Haven

A hospital management system, written in Java. It tracks every bed, admits and discharges patients, prints the bill and runs the payroll. And it refuses anything that would break the hospital's rules.

Front desk

    How it works

    Follow one admission through the system: from whichever screen the desk is using, past the rules, into the database, and out again as a bill.

    1. 1

      Three ways in, one set of rules

      A desktop app, a console and a JSON API sit on top of the same services. None of them holds a rule of its own, so they can't disagree about who is in which bed or what anyone owes.

    2. 2

      The database has the last word

      A room counts as occupied when an active admission points at it. There is no "occupied" flag to forget to update. The schema allows one active admission per room, so two patients in one bed is impossible, not just unlikely. Discharging closes the stay and keeps the patient's record.

      CREATE UNIQUE INDEX uq_active_room
    ON admissions(room_no)
    WHERE status = 'ACTIVE';
    3. 3

      The bill adds itself up

      An invoice is a list of items that price themselves. A room charge is nights × the nightly rate (a part night counts, and no stay is free). A scan or a medicine is quantity × price. Money is kept in whole paise, never as a floating-point number.

      Staff pay works the same way: each kind of staff member works out its own allowance.

      lines.stream()
     .map(BillableItem::lineTotal)
     .reduce(Money.ZERO, Money::plus);

    Why it's built this way

    Each of those choices costs more than the obvious version. So the repository keeps the obvious version too, and a test runs both against the same hospital.

    A bill that forgets the nights

    The tempting formula is rate − deposit. It reads fine until you notice that the rate is the price of one night, so the length of the stay never reaches the bill.

    See the numbers

    Anyone could sign in

    select * from login
where ID = 'admin'
and PW = '' OR '1'='1'
    • The obvious version pastes the password into the SQL, so that password signs anyone in.
    • Health Haven refuses it. What you type is a bound value, never SQL, and passwords are stored as bcrypt hashes.

    Discharge deleted the patient

    DELETE FROM patient_info
WHERE number = '…'
    • The obvious version forgets everyone it discharges. A returning patient is a stranger.
    • Health Haven closes the stay, issues the invoice and keeps the record. Everyone waiting at the front desk was discharged before.

    Two patients, one bed

    UPDATE room
SET availability = 'Occupied'
WHERE room_no = '…'
    • The obvious version keeps a flag that every screen must remember to update. It drifts, and two patients end up in one room.
    • Health Haven works occupancy out from the admissions, and the database refuses the second one.

    All four comparisons run as tests, and side by side with java -jar target/health-haven.jar audit.

    Run it yourself

    You need Java 21 and Maven. There is no database server and nothing to set up: the app creates and seeds its SQLite file the first time it runs.

    $ git clone https://github.com/safdar-hussain1/health-haven.git
$ cd health-haven
$ mvn package     # builds it, runs the 35 tests

# the desktop app
$ java -jar target/health-haven.jar
# the console
$ java -jar target/health-haven.jar cli beds
# the JSON API
$ java -jar target/health-haven.jar serve 8080
# the obvious version against Health Haven
$ java -jar target/health-haven.jar audit
    • Sign in as admin / aurora@35, reception / changeme-desk or dr.iyer / changeme-doc1.
    • The JSON API serves patient data, so it only listens on your own machine and every request needs the token it prints when it starts.
